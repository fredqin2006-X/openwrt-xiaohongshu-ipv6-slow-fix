# 故障排查

## 安装检查不通过

- 缺少 `nftset`：核对 `dnsmasq --version` 的编译功能。先查固件的软件包替换方法，不要直接卸载正在提供 DNS/DHCP 的组件。
- 找不到 `inet fw4`：可能是 fw3、非 nftables 系统，或当前防火墙没有启动。不要为通过检查而创建空的 fw4 表。
- LAN 接口不存在：核对 `ip link show` 和网络页面，以实际 LAN 三层接口作为 `--interface` 参数。
- 默认 DNS 实例检查失败：本项目安装器只支持一个实际加载 `/etc/dnsmasq.conf` 的默认实例；多实例和其他配置位置需自行适配。
- 已有 XHS 安装：同版本同接口会跳过；其他版本先卸载。早期手工版使用原来的 rollback，不能直接覆盖。

## 服务运行但仍留白

先记录故障时间、Wi-Fi、是否所有设备都慢，以及图片、头像、视频中哪些受影响。再检查：

```sh
/usr/libexec/xhs-ipv4-control status
logread -e xhs-ipv4
```

集合空白可能是尚未经过目标解析或学习；只有缓存页面不能证明网络正常。新目标只有 QUIC/加密 DNS、SNI 被 ECH 隐藏、流量未经过指定接口、实际路径由本地代理终止或加速机制绕过钩子，都可能影响覆盖。

没有计数增长也可能只是客户端已用 IPv4；不要因此开启全局 IPv6 封锁。应结合实际连接和新内容加载判断。

## 其他站点异常

本项目使用目标 IP 限制，共享 CDN 地址可能影响其他站点的 IPv6 网页连接。先完整卸载做对照，不要扩大目标集合或封锁整段地址。保留故障发生时间和目标域名即可；不要在公开 Issue 中粘贴账号、Cookie、密钥、家庭完整配置或原始流量。

## 服务反复重启

核对接口是否已存在、tcpdump 是否支持 `-Q in`、Lua 解释器是否可执行。开机接口短暂未就绪可能触发 procd 重试；持续重启需要处理具体错误。项目不会自动安装依赖、写无限备份或定时重启路由器。

## 防火墙重载之后

维护实例会每 15 秒检查表是否存在。表被清除后即使重建，动态地址也需要重新收集，不是立刻恢复所有原有元素。该机制不意味着完整兼容每一种第三方防火墙、加速插件或代理组合。

## 停用后恢复

完整卸载：

```sh
/usr/libexec/xhs-ipv4-uninstall
```

若退出提示 DNS 标记段损坏，先人工检查 `# BEGIN XHS-IPV4` / `# END XHS-IPV4` 是否唯一且配对。脚本遇到异常标记会停止，不猜测要删哪些行。不要直接用旧备份覆盖整份文件，避免丢失后来增加的其他配置。
