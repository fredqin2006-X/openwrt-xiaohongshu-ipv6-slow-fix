# 安装文件、资源与维护

## 文件与写入位置

| 路径 | 用途 | 常态是否写入 |
|---|---|---|
| `/etc/init.d/xhs-ipv4` | procd 服务入口 | 否 |
| `/etc/xhs-ipv4/` | 域名后缀、主机清单、接口、版本 | 否 |
| `/usr/libexec/xhs-ipv4-*` | 控制、监测、学习、卸载程序 | 否 |
| `/etc/dnsmasq.conf` | 本项目独立 DNS 标记段 | 只在安装/卸载时修改 |
| `/etc/xhs-ipv4-backup/dnsmasq.conf.original` | 首次安装前原始配置 | 固定一份，不覆盖，不自动轮转 |
| `/var/run/xhs-ipv4/live.pcap` | FIFO，非普通文件 | 报文仅在内存管道中流动 |
| nftables `targets6` | 运行时 IPv6 地址集合 | 内核内存 |
| 系统日志 | 启动、退出、错误信息 | 依照固件日志策略 |

安装检查和事务使用 `/tmp` 临时文件，完成后删除。它们不属于累计备份。首次安装备份位于权限 700 的目录内，文件权限 600；可能含有用户原有 DNS 配置，应留在自己的路由器上，不要上传到公共 Issue。

卸载只删本项目标记段，避免历史整文件恢复覆盖后来增加的其他设置。原始备份保留供人工核查。

## 资源参考

原始实现一次实际测量的常驻进程 RSS 合计约 6.5 MB，不能据此认定所有设备固定占用 6.5 MB，也不包含内核抓包缓冲、集合内存、临时进程和高并发暂存峰值。RSS 相加也可能重复计算共享页。

CPU 主要消耗在捕获报文、用户态解析、偶发 nft 命令以及每五分钟的 DNS 查询。高吞吐 IPv6 HTTPS、设备数多时占用会提高。首次测量的五秒低负载窗口没有观察到常驻进程 CPU tick 增长，只能说明该窗口很轻，不能推出长期 CPU 恒为 0。

查看进程：

```sh
ps w | grep -E '[x]hs-ipv4|[l]ua /usr/libexec/xhs|[t]cpdump.*live.pcap'
```

用系统 `top` 观察繁忙时占用；若 `top` 支持批处理，也可自行采样。查看某个 PID 的实际常驻内存：

```sh
grep -E 'Name:|VmRSS:|VmSize:' /proc/PID/status
```

将 `PID` 替换为进程号。`live.pcap` 的 `ls -l` 首字符应为 `p`，表示管道，不应是不断增长的普通文件。

## 调整

当前安装器只暴露一个接口参数。安装后配置文件 `/etc/xhs-ipv4/options` 格式为：

```sh
LAN_IFACE=br-lan
```

接口改变后重启本服务，重新核对规则入接口。不要填 IPTV、WAN 或成员物理口来替代实际 LAN 三层接口。

`domains` 控制被识别的后缀，`hosts` 控制定期预查询的主机名。v0.1.0 安装时会将后缀列表写入 dnsmasq 标记段；单独修改 `domains` 并重启本服务**不会同步更新已写入的 dnsmasq 行**。若要变更域名范围，需要人工同步该标记段并验证 DNS，或修改源文件后按卸载/重新安装流程部署。不要添加通用 CDN 域名或整段 IPv6 地址作为快捷修复。

## 升级

1. 保存自己的接口、域名或主机清单修改。
2. 执行完整卸载；这期间本项目限制暂停，dnsmasq 短暂重启。
3. 从新版本目录执行检查和安装，再核对手机的实际体验。

相同版本的安装器会直接退出，不覆盖手动改动。固定原始备份仍是第一次安装前的配置，不代表最近一次升级前状态；需要另一个时间点的备份时应由用户主动创建。

## 对 IPTV 的边界

程序不修改 `/etc/config/network`、`/etc/config/firewall`、`/etc/config/dhcp`、VLAN、IGMP/MLD 或物理口参数，不执行网络服务或整套防火墙重启。它新增自有 nft 表并在安装/卸载时重启 dnsmasq。

这不等于在所有 IPTV 拓扑下都完成了兼容性验证。需确认选中的接口只承担预期 LAN 流量；IPTV 如果依赖同一 DNS 服务，安装/卸载时也可能受 DNS 短暂重启影响。
